# Angel & Devil 角色视觉与前端原型设计

## 目标

为 Angel & Devil 制作一个可直接体验的响应式前端原型。原型需要让用户完成一整局决策：输入纠结的问题、召唤天使或恶魔、在同一轮继续听取双方意见、补充新信息开启下一轮，以及亲自选择 Yes 或 No 并看到结算。

首版重点是验证角色舞台、自由召唤、Turn 分组和胜负反馈是否形成清晰、有吸引力的体验。原型不接入真实模型、账号、数据库或跨设备同步。

## 视觉方向

采用“新塔罗 × 动画赛璐璐”方向。整体应有决策仪式感和轻度戏剧性，同时避免写实宗教、恐怖、儿童化或夸张善恶脸谱。

### 天使 · Yes

- 象牙白与淡金配色，穿带现代剪裁的短斗篷。
- 几何悬浮光环与半透明玻璃质感羽翼形成识别特征。
- 气质温暖、坚定、有行动力；不是天真乐观或空泛鼓励。
- 基础姿态开放，身体略朝向用户和中央舞台。

### 恶魔 · No

- 黑、酒红与暗金配色，穿带锐利结构的长外套。
- 小型黑曜石角与翼状披风轮廓形成识别特征。
- 气质敏锐、克制、有洞察力；不是邪恶、嘲讽或攻击用户。
- 基础姿态收敛，略微侧身审视中央舞台。

### 角色状态

每个角色具备五种可辨识状态：

| 状态 | 角色表现 | CSS 辅助动效 |
| --- | --- | --- |
| 待机 | 中性表情和基础姿态 | 缓慢呼吸、轻微漂浮、环境光变化 |
| 发言 | 身体前倾、表情更有说服力 | 向中央靠近、放大、专属轮廓光与声波粒子 |
| 倾听 | 视线朝向发言方、保持轻微反应 | 降低亮度和饱和度、短促点头或位移 |
| 胜利 | 自信而克制的庆祝姿态 | 放大、上浮、金色或赤红粒子爆发 |
| 失败 | 接受结果的收束姿态 | 后退、降低亮度，不表现羞辱或崩溃 |

角色资产采用透明背景立绘。视觉素材负责角色、服装、姿态与表情，界面光效、漂浮、缩放、位移和粒子由 CSS 实现。

## 界面结构

### 开局页

开局页以产品名称、简短说明和一个核心输入框为主体。用户输入正在纠结的事情后，通过“先听天使”或“先听恶魔”开始。两个角色在输入区两侧形成初次对峙，并通过悬停、聚焦和点击反馈说明它们可以被召唤。

空输入不能开始；界面以内联提示说明需要先写下问题。Enter 默认使用最近选择的角色开始，按钮操作始终保留明确标签。

### 决策舞台

桌面端采用左侧天使、中间共享聊天、右侧恶魔的三栏布局。角色在整个决策过程中持续可见，中间区域包含当前问题、Turn 时间线、输入区、召唤操作与“作出决定”入口。

当前发言角色提高视觉权重并向中央靠近；另一方进入倾听状态。角色立绘本身可点击，点击效果与对应召唤按钮一致。聊天气泡按照实际发生顺序显示，而不是拆成左右两条独立对话。

### 移动端

移动端将两名角色缩为聊天区上方的半身对峙舞台，双方同时可见。当前发言者在不遮挡另一方的前提下略微放大并靠近中央。聊天记录纵向滚动，输入和主要操作位于易触达的底部区域。结算浮层占据主要视口，但保留胜负角色关系。

## 交互与数据流

原型使用前端状态机管理 `intro`、`active`、`thinking` 和 `settled` 四个阶段，并维护当前角色视觉状态。

1. 用户在开局页提交问题，同时选择首位发言者。
2. 系统创建 Decision 和 Turn 1，首位角色进入思考状态。
3. 短暂延迟后，从该角色的模拟回复池选取符合当前轮次的内容，角色进入发言状态。
4. 用户可在不输入新内容时继续召唤任一角色，回复附加到当前 Turn。
5. 用户输入补充信息并选择角色后，系统创建新的 Turn，再生成模拟回复。
6. 用户点击“作出决定”后进入确认层；选择 Yes 或 No 才会结束本局，取消则返回原状态。
7. Yes 对应天使获胜，No 对应恶魔获胜。结算显示最终选择、胜方、双方发言次数、简短收尾和“开始新的决策”。

模拟回复不追求通用语言生成，而是根据角色、当前 Turn 序号、对方是否已经发言以及用户问题中的少量关键词，从若干产品化模板中选择内容。模板必须保持天使支持 Yes、恶魔支持 No，并避免逐字重复。

## 组件边界

- `App`：控制整局阶段和顶层状态切换。
- `StartScreen`：收集初始问题与首位角色。
- `DecisionStage`：组合桌面和移动端舞台布局。
- `CharacterPanel`：呈现角色资产、视觉状态、阵营标签与点击召唤行为。
- `Conversation`：按 Turn 渲染共享时间线。
- `Composer`：处理补充信息、当前轮继续召唤和决策入口。
- `DecisionDialog`：确认 Yes / No，避免误触直接结算。
- `ResultOverlay`：展示胜负动画、本局统计和重新开始入口。
- `mockResponses`：封装模拟回复选择逻辑，与视觉组件隔离。

## 视觉系统

基础背景使用深靛蓝与近黑紫，舞台中心使用暖灰白的羊皮纸/塔罗牌面质感。天使使用暖金与象牙白强调色，恶魔使用酒红与暗赤强调色。边框细而明亮，圆角克制，避免通用后台卡片感。

标题使用具有古典张力的展示字体，正文使用高可读的中文无衬线字体。动画以 180–360ms 的状态切换为主，待机循环放缓至 3–5 秒。系统开启“减少动态效果”时停用漂浮、粒子和大幅位移，只保留颜色与透明度反馈。

## 异常与边界处理

- 开局和新 Turn 的空输入均不会提交。
- 思考期间锁定重复召唤，防止同一操作产生多条回复。
- 用户可取消决策确认并继续聊天。
- 结算后停止所有未完成的模拟回复计时器，旧回复不能覆盖结算状态。
- 重新开始会清空当前 Decision、Turn、统计和角色状态。
- 原型刷新后可重置，不承诺持久化。

## 验证方式

- 手动完成“天使先说”和“恶魔先说”两条完整路径。
- 验证同一 Turn 连续召唤双方不会创建新 Turn。
- 验证输入新消息会创建下一 Turn 并保留此前内容。
- 分别选择 Yes 和 No，确认胜方、失败方、统计和重新开始均正确。
- 验证思考中重复点击、空输入、取消结算和结算时仍有计时器等边界情况。
- 在典型桌面宽度与窄屏移动端验证角色持续可见、聊天可滚动、操作不被遮挡。
- 验证键盘焦点、可见标签、对比度和减少动态效果设置。

## 非目标

- 不接入真实 AI、流式回复、语音或实时口型。
- 不实现登录、云端存储、决策历史或跨局战绩。
- 不实现骨骼动画、3D 角色或 Canvas 游戏引擎。
- 不提供角色换装、性格强度或更多皮肤。
