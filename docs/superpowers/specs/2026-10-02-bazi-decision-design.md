# 八字决策设计

> 2026-10-02 更新：起卦与观命拆为**两个独立功能**，开场以两枚印章供用户择一，也可先说事再选，或直言「起卦」「观命」。
> - 起卦：不问生辰。静心（墨滴入水视频）→ 亲手掷钱六次（静水视频）→ 成卦（涟漪视频）→ 按朱熹《易学启蒙》变爻规则取经文，只依卦理三句文言解卦 → 择行或止，不给吉日。
> - 观命：生辰帖 → 排盘动画（只在初次）→ 依命盘与时机三句文言 → 择行时给三个吉日。
> - 两者互不引用；同一问法下可连问，决定之后下一事重新择法。下文旧章节中与此冲突之处，以本段为准。

## 目标

做一个以八字为依据、帮用户拿主意的对话产品。用户像和一位懂命理的引路人聊天一样说出自己纠结的事；引路人在对话里自然地问到生辰，然后结合「命盘 × 事情类型 × 当下时机」给出解读：这件事的倾向、行与止各自的理由、最合适的时间窗口。用户可以继续追问，最后自己选择「行」或「止」；选「行」时，引路人再给出行动吉日。

**只有一位引路人和用户对话，没有角色之间的对聊或辩论，也没有表单。** 结构化信息全部从对话中提取，必要时在消息里嵌入轻量的确认卡片。

现有天使 / 恶魔美术和花园背景全部弃用，整体画风改为唯美的东方幻想风格。

## 产品原则

- **像聊天，不像填表。** 引路人一次只问一件事，语气温柔、有画面感；用户随口说的信息都能被接住。
- **依据先于结论。** 所有命理判断由本地规则计算，模型负责倾听、追问，并把依据翻译成和这件事相关的人话。
- **既说时机，也说做法。** 回答两个问题：现在宜不宜做；要做的话，什么时候、怎么做更顺。
- **用户拥有最终决定权。** 引路人只给倾向，不替用户裁决；结算由用户点「行」或「止」。

## 引路人

- 名字暂定「司命」（可改），形象是月下执灯的东方仙人：长发、半透明纱衣、手提一盏映着星盘的灯。
- 性格温柔、笃定、有分寸；说话简短，偶尔用一句意象收尾，但不堆砌文言，不故弄玄虚。
- 状态：静候、倾听（用户输入时灯焰轻晃）、推演（星盘在灯中旋转）、诉说、送别（结算）。
- 首版可以先用剪影和灯光的抽象形象，立绘到位后再替换。

## 一局对话

### 阶段

| 阶段 | 引路人在做什么 | 结束条件 |
| --- | --- | --- |
| 问心 | 请用户说出纠结的事，必要时追问一两句现实背景 | 拿到问题，并识别出事情类型 |
| 问生辰 | 首次使用时，自然地询问出生年月日、时辰、出生地、性别；老用户直接跳过 | 信息完整，且用户已确认 |
| 推演 | 本地排盘并计算信号与时机；界面播放星盘推演动画 | 计算完成（毫秒级，动画约 1.5 秒） |
| 解读 | 以三句文言写出结论、时机和一句叮嘱，只有文字，不附命盘或时机图表 | 解读写完 |
| 追问 | 回答用户的追问，如「换成下个月呢」「如果是和朋友合伙呢」，必要时重新计算 | 用户点击「行」或「止」 |
| 择日 / 送别 | 选「行」时给出 3 个吉日；无论哪种选择都用一句话送别 | 一局结束 |

用户在任何阶段都可以直接说出全部信息（如「我 1995 年 3 月 8 号早上 7 点生在杭州，女，在纠结要不要辞职」），引路人会跳过已经拿到的部分。

### 信息提取

每当用户发出消息，先做一次结构化提取（模型调用，输出 JSON）：

```json
{
  "question": "要不要辞职去做自媒体",
  "topic": "create",
  "horizon": "3m",
  "context": "现在工作稳定但没成长，已经攒了半年积蓄",
  "birth": { "date": "1995-03-08", "time": "07:00", "place": "杭州", "gender": "female" },
  "intent": "answer" 
}
```

- `intent` 取值 `answer`（回答引路人的问题）、`followup`（追问解读）、`new_question`（换一件事）和 `chitchat`。
- 缺什么，由引路人在下一句里问什么；`horizon` 没说时默认三个月，不专门追问。
- **生辰必须确认。** 提取出生辰后，引路人的消息里嵌入一张「生辰帖」确认卡（公历和农历对照，时辰以「辰时 07:00–09:00」的形式显示），用户点「是」或直接说出修改。这是唯一的卡片式交互，用来防止排错盘。
- 时辰不详时可以继续，引路人会说明「时柱缺失，看得会浅一些」。

### 事情类型与十神

| 类型 | 主看十神 | 示例 |
| --- | --- | --- |
| `career` 事业 | 正官 / 七杀 | 接不接这个职位、要不要考公 |
| `wealth` 财 | 正财 / 偏财 | 做不做副业、换不换高薪工作 |
| `study` 学业 / 资产 | 正印 / 偏印 | 要不要读研、要不要买房 |
| `create` 创业 / 表达 | 食神 / 伤官 | 要不要辞职做自媒体 |
| `peer` 合伙 / 人际 | 比肩 / 劫财 | 要不要和朋友合伙 |
| `love` 感情 | 男看财星，女看官杀 | 要不要表白、要不要分手 |
| `other` 其他 | 仅看喜用与时机 | 无法归类时兜底 |

## 命理计算（本地、确定性）

### 命盘

`lunar-javascript` 排盘，得到四柱、藏干、十神、日主五行与强弱、五行分布、喜用神 / 忌神、当前大运；出生地用于真太阳时校正。结果存入用户档案，每局保存一份快照。

### 决策信号

`computeSignal(chart, topic, date)`：

```json
{
  "topic": "create",
  "natal": { "effect": "favorable", "note": "伤官透干，有根" },
  "dayun": { "ganzhi": "甲午", "effect": "favorable", "note": "大运木火，扶身" },
  "liunian": { "ganzhi": "丙午", "effect": "favorable", "note": "火为喜用" },
  "liuyue": { "ganzhi": "戊戌", "effect": "unfavorable", "note": "戌冲日支辰" },
  "score": 62,
  "pros": ["流年火旺，正合喜用", "伤官透干，才华有出口"],
  "cons": ["本月日支受冲，计划易被打乱"]
}
```

规则覆盖：主看十神在原局是否透干有根，大运、流年、流月五行是否为喜用，对日柱的冲、合、刑、害。`score` 为四层加权（原局 20%、大运 25%、流年 30%、流月 25%），权重是初始值，需要用样本盘校准。

### 时机窗口与倾向结论

- `computeTiming`：在时间范围内逐月打分，得出倾向曲线和最佳窗口。
- `computeLean`：结论分三档，模型不能改：

| 结论 | 条件（初始阈值，按顺序判断） | 引路人的基调 |
| --- | --- | --- |
| 待时 | 窗口内有比当前高 15 分以上的月份 | 可以做，等到某月更顺 |
| 宜行 | 当前 ≥ 50 | 时机在你这边 |
| 宜止 | 其余情况 | 这段时间不宜强求 |

### 喜用神（首版简化）

首版采用简化的扶抑法：五行按天干 1、藏干本气 / 中气 / 余气 1 / 0.5 / 0.3 计分，月令本气额外加 1；同我与生我占比 ≥ 50% 判为身强，喜食伤、财、官杀，否则喜比劫、印。暂不考虑调候、从格、化气。

### 择日

`pickAuspiciousDays(chart, window, 3)`：日干支属喜用、不冲日柱、避开月破与岁破。

## 解读的说法

解读拆成 3–5 条短消息，像人在说话，而不是一份报告：

1. **结论**：一句话，加一个意象。例如「这件事，你的时机在初夏。」
2. **命盘看这件事**：两三句说清底色。
3. **时机**：解释最佳窗口。
4. **行与止**：先说支持去做的理由，再说要提防的地方，各两三条；每条都是一个命理依据加一句现实落点。
5. **若要行**：一两条可执行的建议，最后邀请用户追问或做决定。

模型约束：

- 只能引用 signal 与 timing 中出现的干支、十神和月份，不得自造。
- 不改写倾向结论，不断言吉凶必然发生，不制造恐惧。
- 追问时，如果涉及新的时间或新的类型，先在本地重新计算，再回答。
- 保留现有 `safetyMode`：`high_stakes` 时提醒以专业意见为准；`crisis` 时不做命理，直接返回现有危机回应。
- 解读生成失败时降级：只写本地算出的三句结论（倾向、最佳月份、一句叮嘱）。

## 决定与回看

- 解读完成后，输入框上方出现两颗常驻的选择：「行」（日色）和「止」（月色）；结论为「待时」时，「行」显示为「待到某月再行」。
- 点击后确认，太极盘向选中的一侧收束，引路人送别；选择「行」时附带吉日卡。
- 历史以「灯笼」或「星笺」列表展示：问题、结论、选择、吉日；过去的决定可以标记结果（顺 / 一般 / 不顺）。

## 视觉方向：唯美东方幻想

- **场景**：月夜湖面。深蓝到青紫的夜空渐变，一轮大月，远山层叠的云雾，湖面倒映星河；花瓣（樱或梨）和萤火缓慢飘落。
- **主体**：引路人立于画面一侧或上方，手中灯盏是视觉焦点；推演时灯中的星盘展开成一个半透明的八卦星图，覆盖舞台。
- **对话**：消息气泡是半透明的磨砂纱质，带细金描边；引路人的消息逐字浮现，像墨在水中化开；用户的消息偏月白。
- **色彩**：主色是夜蓝、月白、淡金；阳面点缀暖金和朱砂，阴面点缀银蓝和雾紫。整体低饱和、高光感，避免大红大黑和庙宇感。
- **字体**：标题用细宋或楷体系的展示字体，正文用清晰的无衬线字体；行距宽松。
- **动效**：花瓣、萤火和水波是常驻的环境动效（3–8 秒循环）；状态切换控制在 240–480ms；开启「减少动态效果」时只保留淡入淡出。
- **移动端**：月亮和引路人缩为顶部的半屏场景，对话占下半屏，选择按钮固定在底部。
- **素材**：背景和引路人需要新生成一套插画（提示词另行整理），首版可以先用 CSS / SVG 渐变、粒子和剪影完成。

## 技术实现（首版）

- `lib/bazi.mjs`：`buildChart`、`computeSignal`、`computeTiming`、`computeLean`、`pickAuspiciousDays`，纯函数，有单测。
- 信息读取：用户的每句话先交给 GPT-6 Luna 提取（`lib/extract-llm.mjs`，不推理、要求输出 JSON，约 3 秒），得到问题、事情类型、时间范围、确认意图以及顺口提到的生辰；司命上一句话会一并交给模型作为上下文。模型只报告「说了什么」：农历由本地历法库换算，所有字段都校验范围，不合格的丢弃。模型调不通时，退回本地规则（`lib/extract.mjs`）。
- 生辰输入：用表单选择，不靠自然语言。需要生辰时，司命写「欲观此事 须知汝之生辰」，写完后浮出生辰帖：公历或农历（可选闰月，月日按农历写法显示）、年月日、时辰或精确时间（也可选不详）、男或女、出生地（城市列表，选「其他」则不做真太阳时校正）。所有选项都不用浏览器原生的下拉框或时间选择器，而用水墨风格的选择器（`components/siming/ink-select.tsx`）：收起时是一道毛笔下划线上的字，展开时是一张宣纸小笺，选项以书法字排成格子（年四列、月三列、日五或七列、时辰三列并附钟点、城市四列），选中项为浓墨实底；支持方向键、回车、Esc，点外面收起，下方空间不够时向上弹出。精确时间用「精确到分」开关切换成时、分两个选择器（分以五分钟为一档）。点「定」后由服务端校验并换算历法，然后直接排盘。对话中顺口提到的生辰会预先填进表单；确认生辰时点「要改」也会打开这张表单。城市表在 `lib/cities.mjs`，前后端共用。
- `lib/guide.mjs`：对话状态机 `advance(state, message | action)`，返回新状态和要输出的步骤（说话、卡片、解读、追问、保存生辰）；还包括本地兜底的解读文案。
- `lib/agent.mjs`：解读与追问的提示词，以及安全分流（`crisis` / `high_stakes`）。
- `app/api/guide`：单一流式接口，SSE 事件为 `state`、`profile`、`say`、`card`、`start`、`delta`、`end`、`done`、`error`。服务端不信任客户端状态，每次都会清洗状态并重新排盘；模型未配置或失败时，改用本地文案。
- 存储：首版不使用数据库。生辰、当前对话和决定记录都存在浏览器 localStorage，可一键删除。旧的 MySQL 持久化（只服务于天使 / 恶魔）已移除，部署只需要配置 `NEVA_API_KEY`。日后如需跨设备，再按「生辰档案 + 决定记录」重新设计表结构。
- 画面：黑白水墨，纯意境，不出现人物，也没有声音。山水背景使用 gpt-image-2 生成的静图，叠加 happy horse 生成的往返循环视频（桌面版和手机版各一段），统一做灰度处理；司命以一个毛笔画的八卦来表现，周围有墨色涟漪，随对话状态变化。排盘时播放 happy horse 生成的水墨八卦视频，四柱干支用书法字体依次浮现，效果像墨在纸上晕开，最后用手绘墨圈圈出日主。素材由 `scripts/generate-media.mjs` 生成。
- 对话呈现：没有聊天框，所有内容都在屏幕正中，一次只出现一个问题（或一屏解读）。司命以简古自然的文言说话，取法《周易》卦爻辞与古人笔记小品，读来像古人随口所言，而不是把现代句子换几个虚词的「翻译腔」：少用「吾」「汝」，不堆砌虚词，不用现代词语（时机、规划、预算、规模等），能用古人现成说法的就用（如「利有攸往」「知止不殆」「量入为出」）；危机安全提示仍用白话。AI 解读只写三句、合计不超过四十字，追问不超过二十字，固定话术同样短，不复述用户的问题；免责说明常驻页面底部，不写进每次回复。书写时不出现任何标点：标点处空一格作为停顿，分段则另起一列；阿拉伯数字写成汉字（二〇二六年、五十八分）。文字竖排，从右往左、自上而下，每个字按真实笔顺用毛笔写出，严格一个字写完再写下一个：字形取自书法字体（马善政楷书），先量出字形实际范围、缩放进笔顺数据的标准字框，再由一支宽笔刷沿 hanzi-writer-data（Arphic 公共许可，经 `/api/strokes` 从本站提供）的笔画中线依次刷出，每笔先慢后快再收；写完一字后补全笔锋；字上加墨边加粗、少量飞白，以及一圈淡淡的湿墨晕。点一下可以直接显示全文；刷新页面后，当前这一屏也会从第一笔重新写起。动笔前先按全文排好每个字的位置（未写的字先占位），所以书写时已写好的字不会挪动，严格从最右列往左写；为此要等整段回复收全才动笔，等待期间屏幕中间显示三个墨点。书写位置不显示跟随的墨点。卡片在文字写完后出现在文字左侧（手机上在下方）。用户回答后，这一屏模糊、上浮、淡出，约半秒后下一屏开始书写。屏幕正中背后是一枚淡淡旋转的水墨八卦。背景由 WebGL 绘制：山水视频（或静图）作为纹理，按水面起伏折射采样，涟漪经过处画面会真实扭曲，并带波峰反光、波谷墨影。湖面上会随机落水滴；用户回答时，输入横线附近落一滴；司命开口时，画面中部落一滴；推演期间水滴持续落在中央附近。设备不支持 WebGL 或开启了「减少动态效果」时，退回普通的视频背景。输入只有一道居中的毛笔横线和一个「答」字。做过的决定可以在「回看」里查看。GPT-6 Luna 会先推理再作答，输出上限设为 3000 token，避免推理用尽额度导致正文为空。
- 前端：`InkScene`（宣纸底和 CSS / SVG 画的水墨山峦、墨滴、雾气、浮动的干支字，画作素材缺失时作为兜底）、`Guide`（毛笔八卦，五种状态）、对话、`BirthCard` / `BirthForm` / `DaysCard`（竖写吉日笺）；命盘数据只用于排盘动画，不再作为卡片展示，以及回看与生辰抽屉。

## 合规与文案

- 定位为「东方决策陪伴 / 自我觉察」，避免「算命」「预测」「改运」等措辞。
- 引路人第一次给出解读时，以及在结算页，都要提示「命理只是一个看问题的角度，决定权在你」。
- 生辰属于个人敏感信息：只存必要字段；用户随时可以说「忘掉我的生辰」或在设置里一键删除。

## 验证方式

- `bazi` 单测：用已知生日对照权威排盘，核对四柱、十神和大运起运，覆盖节气交接日、早晚子时和时辰不详。
- `extract` 测试：一次说全、分多次说、中途修改生辰、口语化表达（如「九五年」「早上七点多」「属猪那年」）、换一件事。
- 对话路径：新用户完整走一局；老用户跳过问生辰；三种结论各走一遍；追问时触发重新计算；行动、择日；回看并标记结果。
- 抽样检查模型输出中没有 signal 以外的干支；解读失败时的降级可用。
- 高风险与危机输入的行为符合预期；移动端布局，以及减少动态效果的设置。

- 不做多角色对话或辩论，不做表单式输入。
- 不做合婚、流年详批、大运逐步解读、紫微斗数、六爻起卦。
- 不做付费解读或真人命理师。
